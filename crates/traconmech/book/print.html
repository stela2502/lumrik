TraConMech — Scientific Methods Handbook

Scientific overview

TraConMech begins with a nominated gene (for example TP53) and a biological comparison such as mutation-bearing versus wild-type cells. It searches the supplied STRING association network for partners of the nominated gene, connects partner names to regulatory gene sets from the configured Ommverse/MSigDB data, and assembles candidate target genes. These associations nominate hypotheses; they do not prove physical binding, direction of regulation, or causation.

For each candidate gene, TraConMech measures expression in case and control cells within the same annotated population. It then groups genes that show similar patterns of relative expression change across populations. A model created from those groups stores module membership and population-level reference centroids. Applying that model to another dataset uses the original modules without refitting them.

The principal trajectory figures answer a straightforward question: within a given cell population, do cells in the two conditions differ in the average expression of the module's genes? Each cell contributes one observation (the mean of its available module-gene log1p values). The figures show group means and approximate 95% confidence intervals. Two-sided Welch tests compare groups, and Bonferroni correction accounts for all module-by-population comparisons in that trajectory output.

A separate AddModuleScore-style calculation subtracts an expression-matched control-gene background from each cell's module-gene mean. That score is exported for interpretation and visualization; it is not the quantity tested in the trajectory figures.

The current inference is descriptive/exploratory at the cell level. Cells sampled from one patient or experiment are not independent biological replicates; corrected p-values therefore do not establish a patient-level effect or a rescue mechanism. Read Statistics and limitations before interpreting small effects.

Investigation and module discovery

Implementation: src/regulatory.rs (run, stats, effect_modules, stability_weight); src/experiment.rs.

Candidate genes

The nominated gene is resolved against the supplied STRING protein-info table. Direct incident edges in the supplied STRING links table are retained when combined_score >= --string-min-score; a headered full links file or headerless standard three-column file is supported. Protein identifiers are mapped to preferred gene names. Partner symbols are matched to configured regulatory gene-set names by underscore-delimited symbol tokens. The union of the matching sets' genes forms the candidate list. A gene may occur in several sets, but this is not a statistical enrichment test.

Within-population comparisons

For gene \(g\), population \(k\), and condition \(h\), let \(x_{gc}\) denote the supplied expression-matrix value (expected to be log1p-transformed). Define

\[ \mu_{gkh}=\frac{1}{n_{kh}}\sum_{c\in C_{kh}}x_{gc},\qquad r_{gk}=\log_2\left(\frac{\mu_{gk,\mathrm{case}}+0.01}{\mu_{gk,\mathrm{control}}+0.01}\right). \]

Important: \(r_{gk}\) is the log2 ratio of means of log1p values; it is not a log2 fold change of raw counts. The pseudocount 0.01 is applied to those means. The code also reports detection fraction (nonzero values), and a population-standard-deviation with divisor \(n\) for the gene-level summaries.

Only populations with both observed conditions enter these effects. The implementation explicitly does not substitute WT cells from a different population. --co-variant-clusters can select and order a specific sequence, and fails if a selected population lacks a comparison.

Discovering modules from effect profiles

For each gene, form the effect vector \(\mathbf r_g=(r_{g1},\ldots,r_{gK})\). Center it and normalize its Euclidean length:

\[ \mathbf z_g=\frac{\mathbf r_g-\bar r_g\mathbf 1} {\lVert\mathbf r_g-\bar r_g\mathbf 1\rVert_2}. \]

Genes with fewer than two entries or centered norm below 1e-9 enter module 0 (flat/uninformative trajectories). Remaining genes undergo deterministic spherical k-means-like clustering: at most eight initial centers, farthest-first initialization, cosine/dot-product assignment, normalized centroid updates, at most 40 iterations, deterministic gene-name iteration and tie resolution. Modules are numbered from 1. Eight is a cap, not a guarantee of eight modules. Module IDs are labels, not effect magnitudes.

A separate stability weight used in reporting/ranking is

\[ D=\tfrac12\left(\frac{\sigma_{\rm case}^2}{\mu_{\rm case}+0.1} +\frac{\sigma_{\rm control}^2}{\mu_{\rm control}+0.1}\right),\qquad w=\frac{1}{1+D}. \]

The code sets \(w=0\) when the maximum condition mean or detection fraction is below 0.05. These weights rank/report gene evidence; they do not define the module assignments, which use the centered effect profiles above.

Key files: effect_clusters.tsv, module_membership.tsv, effect_modules.tsv, module_measurements.tsv, stable_module_genes.tsv, wt_reference_clusters.tsv, plus STRING/partner evidence tables. Module 0 remains auditable but is not plotted as an ordinary module.

Frozen gene models

Implementation: src/main.rs (Mode::GeneModel), src/gene_model.rs, src/experiment.rs.

gene-model create

The CLI loads an H5AD file or Matrix Market directory, resolves the experimental design, and runs the regulatory investigation with effect-module discovery enabled by --effect-cluster. create then reads module_membership.tsv from the output directory; model creation requires nonempty modules. The portable JSON stores the nominated gene, training grouping name, feature names, frozen gene-to-module assignments, and one expression centroid per training population:

\[ \mathbf m_k(g)=\frac{1}{|C_k|}\sum_{c\in C_k}x_{gc}. \]

These are means of supplied log1p values, not re-log-transformed or back-transformed counts. The model format is traconmech.gene-model.centroids, version 1. The saved centroids are reference metadata; the subsequent module-scoring implementation does not classify external cells by nearest centroid.

gene-model apply

The CLI validates the model's gene identity and loads the external data. At least 10 shared features and at least 50% overlap with all model features are required. The model's original module memberships are used unchanged. apply writes per-cell background-corrected scores, uncorrected module-gene means, condition summaries and feature coverage. It also generates module UMAPs when the input is an H5AD file, and frozen-module trajectory plots using the original model gene sets.

Crucial processing-path detail: gene-model apply can additionally run a fresh regulatory investigation on the external data when both comparison conditions are present, but sets effect_cluster=false for that path. That investigation is not the same as refitting the saved model. When a condition is absent, the differential regulatory investigation is skipped and frozen-model outputs still run.

Experimental configuration and reproducibility

experiment::resolve uses condition annotations and explicit or resolved case/control labels, storing decisions in experiment.yaml. Keep that file with the model, input provenance, reference versions and command invocation. Never delete or silently replace it during reruns. Some generated outputs are rewritten when commands run; protect run directories and archive input configuration before regeneration.

Key files: portable model JSON, gene_model_training_clusters.tsv, gene_model_scores.tsv, gene_model_module_means.tsv, gene_model_condition_scores.tsv, gene_model_module_coverage.tsv, gene_model_coverage.json, frozen_module_coverage.tsv, module_trajectories.tsv, module_*_trajectory.svg.

Module scoring: two different measurements

Implementation: src/module_score.rs (score); used by src/gene_model.rs and src/module_plots.rs.

Let \(x_{gc}\) be the supplied expression of gene \(g\) in cell \(c\), already on the log1p scale. For a frozen module \(M_j\), only genes present in the current dataset are used: \(M'j=M_j\cap G{\rm observed}\).

Uncorrected module-gene mean

For each cell, TraConMech computes

\[ A_{cj}=\frac{1}{|M'j|}\sum{g\in M'j}x{gc}. \]

Zeros contribute to the denominator. The software does not apply ln_1p a second time. This uncorrected per-cell mean is written to gene_model_module_means.tsv and is the input to the trajectory statistics. If a module has no observed genes, scoring fails.

Expression-matched control background

To calculate a separate AddModuleScore-style score, the program computes each gene's mean across all cells (including zeros), ranks genes by this mean (breaking ties by gene index), and partitions the rank order into 24 approximately equal-sized bins.

For each module gene, it selects up to 100 genes from that gene's bin, sampled without replacement using an explicitly seeded deterministic xorshift-like PRNG. The selections are unioned and deduplicated across module genes to form a module-specific control set \(B_j\). The implementation does not explicitly exclude module genes from this control set; do not describe it as a disjoint negative control.

The background and corrected score are

\[ B_{cj}=\frac{1}{|B_j|}\sum_{g\in B_j}x_{gc},\qquad S_{cj}=A_{cj}-B_{cj}. \]

gene_model_scores.tsv contains \(S_{cj}\); best_module is simply the largest score in that cell. gene_model_condition_scores.tsv summarizes scores per condition and uses a population (divisor-\(n\)) SD. The plotted trajectory means, confidence intervals and p-values use \(A_{cj}\), not \(S_{cj}\).

The method is Seurat-style, not a claim of bit-for-bit equivalence with Seurat's AddModuleScore: exact binning, sampling PRNG, duplicate handling and gene universes can differ.

Module trajectories and plots

Implementation: src/gene_model.rs::plot_frozen_modules, src/module_plots.rs::write_module_plots_named.

Each plotted x-position is an annotation category, not a numerical time point. For each frozen nonzero module \(j\), category \(k\) and condition \(h\), the plotted ordinate is the mean across contributing cells of their uncorrected module-gene means \(A_{cj}\). Blue denotes reference/control; red denotes case. An absent condition is a gap, not a zero or an imputed reference.

The error bars are approximately 95% normal confidence intervals for the cell-level mean, \(\bar A\pm1.96,s/\sqrt n\), not gene-to-gene dispersion or multiplicity-adjusted confidence intervals. When \(n<2\), the code cannot produce a finite SD/CI. Counts under the plot reflect observed cells in the respective category. Adjusted p-values and stars come from the separate Welch/Bonferroni procedure in Statistics and limitations.

The x-axis annotation sequence is cell counts → corrected p-value → category label → optional cell-type annotation. --label-angle 0 makes category labels horizontal; supported angles are 0–85 degrees. --count-label-layout supports horizontal and rotated.

Population ordering follows explicitly requested --co-variant-clusters, or relevant H5AD categorical/developmental metadata; a separate AI-suggested developmental order may generate module_trajectories_developmental.tsv and module_*_trajectory_developmental.svg. Lines between categories are visual guides; without a justified biological order, they do not establish a developmental trajectory. The analysis-wide correction in each output is computed from its modules and displayed categories; changing the set of categories can change the correction factor.

Outputs: module_trajectories.tsv and module_<id>_trajectory.svg (and optional _developmental counterparts). TSV rows are per module × category × condition; the same comparison's p-value and effect are therefore repeated in the two condition rows. genes is the number of module genes, while n_cells counts observations in that condition. See Statistics and limitations for the column definitions.

Statistical analysis and limitations

Implementation: src/module_plots.rs::{cell_stats,welch_test,p_label,write_module_plots_named}. This chapter documents the code after the supplied CI and Bonferroni patches; it does not claim an independent validation study.

Observation and estimand

For module \(j\), population/phase \(k\), and condition \(h\), each cell \(c\) contributes one uncorrected module mean \(A_{cj}\). The comparison estimates

\[ \Delta_{jk}=\bar A_{jk,\mathrm{case}}-\bar A_{jk,\mathrm{control}}. \]

Thus a positive value indicates higher average log1p expression in case cells. The effect is not a log fold change of counts, and it is not a difference of background-corrected module scores.

Confidence intervals

Within each condition, the code computes the sample SD using \(n-1\) and draws

\[ \mathrm{CI}_{95%}(\bar A)=\bar A\pm1.96\frac{s}{\sqrt n}. \]

These are normal-approximation individual-group intervals, not Welch confidence intervals for \(\Delta\), and not simultaneous Bonferroni-adjusted intervals. For fewer than two cells, SD and CI are unavailable.

Two-sided Welch test

For case and control, let \(\bar A_1,\bar A_0\) be group means, \(s_1,s_0\) their sample SDs, and \(n_1,n_0\) their cell counts. The implementation calculates

\[ V_1=\frac{s_1^2}{n_1},\quad V_0=\frac{s_0^2}{n_0},\qquad t=\frac{\bar A_1-\bar A_0}{\sqrt{V_1+V_0}}, \]

\[ \nu=\frac{(V_1+V_0)^2}{V_1^2/(n_1-1)+V_0^2/(n_0-1)},\qquad p_{\rm raw}=2\Pr(T_\nu\ge |t|). \]

The survival probability is calculated with statrs::distribution::StudentsT. A test is unavailable (NA) if either group has fewer than two cells, the pooled standard-error variance is nonpositive/nonfinite, or the degrees of freedom are invalid. This is a two-sided, unequal-variance, cell-level test.

Bonferroni family and annotations

For each trajectory output, the code counts nonzero module IDs \(J\) and plotted population/phase categories \(K\), then sets

\[ m=J,K,\qquad p_{\rm Bonferroni}=\min(1,;m,p_{\rm raw}). \]

Untestable module × category combinations are still counted in \(m\), conservatively. In an output with eight modules and three phases, \(m=24\). The factor is determined by that output's modules and displayed categories; it is not a hardcoded 24. If an optional developmental-order output contains a different set of categories, its family can differ. This implementation does not automatically combine separate analysis runs into a single multiplicity family.

SVG labels show the adjusted p-value in scientific notation, prefixed with * if \(p_{\rm Bonferroni}<0.01\), ** if \(p_{\rm Bonferroni}<0.001\), and no star otherwise. p=NA means no valid test. The plot legend reports the factor and its module × category components. The thresholds are intentionally not the conventional 0.05/0.01 pair.

The TSV records mean_log1p, sd, se, ci95_low, ci95_high, n_cells, case_n, control_n, delta_mut_minus_wt, welch_t, welch_df, p_raw, p_bonferroni, and bonferroni_factor. The field delta_mut_minus_wt is named for the TP53 comparison, but mathematically means configured case minus configured control, whatever their labels.

What the p-value cannot establish

  1. Pseudoreplication: cells from one patient, library, culture or sample are not independent biological replicates. A small cell-level p-value is not a patient-level inference. Biological replication and hierarchical/pseudobulk analysis are needed for generalizable claims.
  2. Post-selection inference: modules are discovered using observed case–control effects in the training data. Testing the same data with those selected modules can make nominal p-values anti-conservative. Bonferroni across plotted modules/phases does not correct the earlier selection step. Independent validation on held-out samples is preferable.
  3. Dependence and scale: modules and phases can be correlated; Bonferroni remains conservative under arbitrary dependence for a prespecified family of valid p-values. Means of log1p values are not count fold changes.
  4. Small effects: with many cells, statistically convincing differences can still be biologically negligible. Always inspect \(\Delta\), group means, coverage, sample origin and trajectory shape.
  5. No causal proof: neither a STRING association nor a gene-set match establishes a TP53 regulatory mechanism or functional rescue.

Output interpretation

  • module_membership.tsv: training gene → exclusive module assignment (including possible module 0).
  • gene_model_scores.tsv: per-cell background-corrected module score, plus highest-scoring module.
  • gene_model_module_means.tsv: per-cell uncorrected module mean on the supplied log1p scale.
  • module_trajectories.tsv: condition-wise summary of those uncorrected means; one Welch comparison per module × category, repeated on the two condition rows.
  • module_*_trajectory.svg: means, approximate individual-group 95% CIs, cell counts and adjusted p-values.
  • experiment.yaml: analysis-design decisions; retain with results.
